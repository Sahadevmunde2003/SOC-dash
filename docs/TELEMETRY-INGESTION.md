# Raw Lab Telemetry Ingestion

These endpoints are intended for local, authorized lab data. They parse the provided text and return normalized events plus detections. They do not tail files, connect to appliances, or persist raw events to disk.

## Ubuntu SSH authentication log

Send the contents of an exported or copied auth log to:

- Method: POST
- Path: /api/ingest/auth-log
- JSON body: {"content": "full auth.log text"}

Example from the repository root, with the API running on 127.0.0.1:5000:

```bash
python - <<'PY'
import json
from pathlib import Path
import urllib.request

payload = json.dumps({"content": Path("backend/data/sample-auth.log").read_text()}).encode()
request = urllib.request.Request(
    "http://127.0.0.1:5000/api/ingest/auth-log",
    data=payload,
    headers={"Content-Type": "application/json"},
    method="POST",
)
print(urllib.request.urlopen(request).read().decode())
PY
```

The parser recognizes sshd failed-password and accepted-password/public-key records. The starter SSH detection flags five or more failed logins from one source IP within 120 seconds. This is a simple lab rule, not a production-grade correlation engine.

## pfSense JSONL export

Send newline-delimited JSON records to:

- Method: POST
- Path: /api/ingest/pfsense
- JSON body: {"content": "one JSON object per line"}

Example using the included fixture:

```bash
python - <<'PY'
import json
from pathlib import Path
import urllib.request

payload = json.dumps({"content": Path("backend/data/sample-pfsense.jsonl").read_text()}).encode()
request = urllib.request.Request(
    "http://127.0.0.1:5000/api/ingest/pfsense",
    data=payload,
    headers={"Content-Type": "application/json"},
    method="POST",
)
print(urllib.request.urlopen(request).read().decode())
PY
```

The parser requires an ISO-8601 timestamp, valid source and destination IP addresses, and an action of pass, block, or reject. Invalid lines are reported in the response under errors; valid lines continue to be processed.

## Response fields

- parsed_count: number of normalized events.
- error_count and errors: per-line parse/validation problems.
- events: normalized records returned for review.
- detections: alerts generated by the starter rules and inserted into the in-memory alert list.

## Limitations and safe use

- The API binds to loopback by default. Do not expose it directly to an untrusted network.
- The current store is in memory; generated alerts disappear when the API restarts.
- The parser uses the current UTC year for syslog timestamps that omit a year; pass an explicit year in parser unit tests.
- Starter thresholds are fixed defaults and require tuning to your lab baseline.
- Fixtures use documentation IP ranges and are synthetic. No external reputation lookups or live telemetry connections are performed.
- For production use, add authentication, rate limits, persistence, structured audit logs, configurable rules, and stronger parsing for the exact pfSense export format you use.
